# タスク整合性チェックスキル

指定されたカテゴリまたはIssue配下の既存タスクが、上位目標・戦略と整合しているかを検証する。
`/task-plan` が「新規作成時の設計」なのに対し、こちらは「既存タスクの監査」。

## 引数
- `$ARGUMENTS` = チェック対象のID（例: `1-B`, `1-B-01`, `3-A`）
- 空の場合はプロジェクト全体をチェックする（サマリーレベル）

## 手順

### 1. データ読み込み（並列実行可能）
- `github_sim3/STRATEGY.md` — 戦略全体（ビジョン・柱・フェーズ・KPI・移行条件）
- `github_sim3/issues.yaml` — タスクツリー全体
- 指定IDに属するタスク詳細ファイル（`github_sim3/tasks/{id}.md`）を全て読み込む

### 2. 上位→下位の整合性チェック（トップダウン）

以下の階層で、上位の目的が下位に正しく分解されているか確認する:

```
ビジョン（広島を元気にする）
  └ 柱（AIアート / 業務効率化）
    └ フェーズ（基盤構築 / コミュニティ確立 / 拡大 / マツダ）
      └ カテゴリ（A, B, C...）
        └ Issue（具体的な課題）
          └ タスク（実行可能な作業単位）
```

各レベルで以下を検証する:

#### チェック① 目的の連鎖（なぜこのタスクが必要か）
- 各タスクは親Issueの目的達成に貢献するか？
- 親Issueはカテゴリの目的達成に貢献するか？
- **「このタスクを全て完了したら、親の目的は達成されるか？」** を問う
- 貢献しないタスクは「不要 or 配置ミス」として報告する

#### チェック② 網羅性（何が足りないか）
- 親の目的を達成するために、子タスクに**抜け**がないか？
- 例: 「商工会と接点を作る」が目的なのに「アプローチ準備」タスクがない
- MECE（漏れなくダブりなく）に近いかを評価する

#### チェック③ 粒度の均一性
- 同じ階層のタスクで粒度がバラバラでないか？
- 例: 「名刺印刷」（1時間）と「AI活用支援の実施」（数週間）が同列にある
- 大きすぎるタスクは分解を、小さすぎるタスクは統合を提案する

#### チェック④ 順序と依存関係
- タスクの実行順序に論理的な飛躍がないか？
- 暗黙の依存関係（AをやらないとBができない）が明示されているか？
- 完了済みタスクの成果物が、後続タスクで活用されているか？

#### チェック⑤ 2本柱との整合（新戦略固有）
- 各タスクは「アート系」「業務系」「共通基盤」のどれに該当するか？
- 2本の柱に対するバランスは適切か？
- STRATEGY.mdのKPI・移行条件に貢献するタスクが存在するか？

### 4. ユーザーとの対話
- 結果を表示した後、改善提案の実施について確認する
- タスクの追加が必要な場合は `/task-create` の使用を案内する
- タスクの修正は issues.yaml と tasks/{id}.md を直接編集する
