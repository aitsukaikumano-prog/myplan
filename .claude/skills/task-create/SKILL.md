# タスク作成スキル

新規タスクを整合性チェック付きで3ファイルに登録する。
引数: `/task-create 1-A-01-4 スキル棚卸しの更新` のように渡す。

## 引数の解析方法
- `$ARGUMENTS` 全体を空白で分割する
- **最初の単語** = タスクID（例: `1-A-01-4`）
- **残りすべて** = タスクタイトル（例: `スキル棚卸しの更新`）
- どちらかが欠けている場合はユーザーに入力を求めて終了する

## 手順

### 1. 引数のバリデーション
- タスクIDが命名規則 `{数字}-{英字}-{数字2桁}` または `{数字}-{英字}-{数字2桁}-{数字}` に従っているか確認する
- タイトルが空でないことを確認する

### 2. コンテキスト読み込み（並列実行可能）
- `github_sim3/issues.yaml` を読み込む
- `github_sim3/STRATEGY.md` を読み込む

### 3. 整合性チェック（作成前に必ず実施）

以下の3項目をチェックし、問題があればユーザーに報告する:

#### チェック① 配置の妥当性
- タスクIDの親（Issue/カテゴリ/戦略）が存在するか？
- 同じIDが既に存在しないか？
- 親Issueの目的とタスクの内容は一致しているか？

#### チェック② 前提条件
- このタスクを始めるために、先に完了すべきタスクはあるか？
- その先行タスクは完了済みか？
- 未完了の先行タスクがある場合は警告する

#### チェック③ 隣接タスクとのギャップ
- 同じIssue内の既存タスクと合わせて、目標達成までの流れに抜けがないか？
- 例: 「企画」→「開催」の間に「告知」が必要ではないか？
- ギャップがあれば「追加タスクの提案」として報告する

#### チェック④ 兄弟パターンの踏襲（Issue追加時は必須）
- **同一カテゴリ内の既存Issueが持つタスク構成を確認する**
- 共通パターンがあれば、新Issueにも同じパターンのタスクを含める
- 例: 1-C配下のIssueがすべて「ポートフォリオ化」タスクを持つなら、新Issueにも必要
- チェック方法:
  1. 親カテゴリ配下の全Issueのタスクタイトルを一覧する
  2. 複数Issueに共通するタスク（名前・役割が類似）を抽出する
  3. 新Issueにそのパターンが欠けていれば⚠️として報告する
- **これは「他がやっているから」ではなく「同じ目的なら同じ完了要件が必要」という論理**

**チェック結果の表示形式:**
```
📋 整合性チェック結果:
  ✅ 配置: 戦略{N} > {カテゴリ} > {Issue} 配下に追加
  ✅ 前提: 先行タスクなし（または全て完了済み）
  ⚠️ ギャップ: {Issue}の完了には「○○」タスクも必要かもしれません
  ⚠️ 兄弟パターン: 同カテゴリの他Issueは「○○」タスクを持っています
```

- ❌（致命的エラー）がある場合は作成を中止する
- ⚠️（警告）がある場合はユーザーに確認した上で続行する
- すべて ✅ の場合はそのまま作成に進む

### 4. issues.yaml にタスク追加
- 該当する親Issue/カテゴリ配下の `tasks:` リストに追加する:
  ```yaml
  - id: "{タスクID}"
    title: "{タイトル}"
    status: "open"
  ```
- **インデントに細心の注意を払う**（スペース2つベース、周囲の既存エントリと揃える）

### 5. tasks/{id}.md を作成
- `github_sim3/tasks/{タスクID}.md` を以下の雛形で作成する:
  ```markdown
  ---
  successCriteria:
    - "TODO: 完了条件を記入"
  outputs: []
  ---

  ## 詳細説明

  {タイトル}

  ## メモ

  ### YYYY-MM-DD 作成
  - /task-create で新規作成
  ```

### 6. tasks/index.yaml にファイル名を追加
- `github_sim3/tasks/index.yaml` の `files:` リストに `"{タスクID}"` を追加する
- コメントで区切られたセクション（Strategy区分）の正しい場所に挿入する

### 7. 依存関係グラフの更新
- `mazda-sync-app/src/components/DependencyGraphView.tsx` の `buildGraph()` を開く
- 該当するsubgraph内にノードを追加: `ID["タイトル<br>タスクID"]:::${c('タスクID')}`
- 依存関係がある場合は矢印を追加: `A --> B` or `A -.->|ラベル| B`
- 移行条件に貢献する場合は `ID --> TC{N}` を追加

### 8. 結果報告
- 整合性チェック結果を再掲する
- 更新した4ファイルの変更箇所を報告する（issues.yaml, tasks/{id}.md, index.yaml, DependencyGraphView.tsx）
- 「`successCriteria` を具体的に記入してください」と促す
- ⚠️ があった場合は追加タスクの作成を提案する
- Git操作は行わない（ユーザーが `/commit-push` で別途実施）
