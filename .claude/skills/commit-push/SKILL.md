# コミット＆プッシュスキル

現在の変更をすべてコミットしてリモートにpushする。

> **注意**: このスキルの呼び出し自体がユーザーのGit操作への明示的同意とみなす。

## 手順

1. **現状確認**（並列実行可能）
   - `git status` で変更ファイルを一覧表示する
   - `git diff` でステージされていない変更を確認する
   - `git diff --staged` でステージ済みの変更を確認する
   - 変更がない場合は「コミットする変更がありません」と報告して終了する

2. **変更内容の分析**
   - 変更されたファイルの種類と内容を分析する
   - 適切なprefixを決定する:
     - `feat:` — 新機能・新タスク
     - `fix:` — バグ修正
     - `docs:` — ドキュメント更新
     - `refactor:` — リファクタリング
     - `chore:` — 設定変更・雑務
   - `.env` やクレデンシャルファイルが含まれていないか確認する（含まれていたら警告して除外）

3. **コミットメッセージの提案**
   - 分析結果から日本語のコミットメッセージを生成する
   - **具体性ルール（必須）**:
     - 「何を」「どう変えたか」が第三者にも伝わるレベルで書く
     - ❌ 悪い例: `refactor: issues.yamlを新戦略に整合`（何をどう変えたか不明）
     - ✅ 良い例: `refactor: 戦略タイトルから月数表記を削除、戦略4「マツダアプローチ」の枠を追加`
     - 変更ファイルが複数ある場合は主要な変更を列挙する
     - 1行目は50文字以内を目安に、超える場合は本文で補足する
   - ユーザーに提案して承認を得る（承認前にコミットしない）

4. **コミット＆プッシュ**
   - `git add` で関連ファイルをステージする（`git add -A` は使わず、ファイルを明示指定する）
   - HEREDOC形式でコミット:
     ```bash
     git commit -m "$(cat <<'EOF'
     {prefix}: {承認されたメッセージ}

     Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
     EOF
     )"
     ```
   - `git push origin main`

5. **結果報告**
   - コミットハッシュとpush結果を報告する
