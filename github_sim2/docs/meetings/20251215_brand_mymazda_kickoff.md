## 📝 議事内容

### 1. プロジェクト概要説明

**発言者**: @daiki
**内容**:
- MyMazdaアプリと販売店CRMをリアルタイム連携し、顧客来店前に車両状態を把握
- 油脂類交換時期、バッテリー健康度などを事前に把握することで、最適な提案が可能に
- 「お客様が言う前に気づく」サービス体験を目指す

**質疑**:
- @yamamoto: 「車両データの取得にはユーザー同意が必要では？」
- @daiki: 「同意取得フローも含めてUX設計する予定」

### 2. 技術的な実現可能性の確認

**発言者**: @tanaka (IT部門)
**内容**:
- 車載コネクティッドユニットから取得可能なデータは約40項目
- 現状のサーバー負荷を考慮すると、リアルタイム同期は厳しい
- 1日1回のバッチ処理が現実的

**決定事項**:
- [x] まずは取得可能データの全リストアップを行う → 担当: @daiki, 期限: 2025-12-25

### 3. プライバシー・法務面の課題整理

**発言者**: @yamamoto (法務部門)
**内容**:
- 個人情報保護法の観点から、位置情報・運転行動データは「要配慮」
- オプトイン形式での同意取得が必須
- 同意撤回時のデータ削除フローも設計が必要

**決定事項**:
- [ ] プライバシーポリシー準拠のUX設計 → 担当: @kenji, 期限: 2026-01-15
