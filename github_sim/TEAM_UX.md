# チームUX：GitHub-First 運用ガイド

## 1. 目的
「会議のための会議」と「報告のための報告」をゼロにし、エンジニアが純粋な創造（Value Creation）に集中できる環境を作る。

## 2. 三原則 (Three Pillars)
1.  **非同期承認 (Async Approval)**: 
    - 意匠や仕様の決定は、対面会議ではなくGitHubのプルリクエスト（PR）またはIssue上で行う。
    - 上司（マネージャー）はIssueのコメントで承認の意志を示し、それが公式記録となる。
2.  **進捗は「跡」で語る (Activity as Status)**:
    - 週報や日報を作る時間は無駄。GitHubの更新ログ（コミット、Issue移動、コメント）自体を進捗とする。
3.  **ブロッカーの即時可視化 (Instant Blocking)**:
    - 困りごとは「次回の定例」を待たずに即座にIssue化し、関係者をメンションする。
